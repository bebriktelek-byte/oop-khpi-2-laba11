## 📝 Опис проекту
Цей проект є консольним Java-застосунком, який демонструє практичні навички використання стандартних колекцій Java (Collections Framework). Модель описує процес автоматизації документообігу на підприємстві.

### Класи предметної області:
* `Employee` — співробітник компанії (автор або погоджувач).
* `ApprovalStep` — окремий етап погодження документа із фіксацією статусу та коментаря.
* `Document` — документ, що містить чергу етапів погодження.

---

## 🛠️ Обґрунтування вибору колекцій
У проекті використано дві різні стандартні колекції для вирішення специфічних інженерних задач:
1.  **`Map<String, Document> (HashMap)`** — використовується як основне внутрішнє сховище реєстру. Забезпечує швидкий пошук, додавання та видалення документів за їхнім унікальним ідентифікатором (ID) за константний час $O(1)$.
2.  **`Queue<ApprovalStep> (ArrayDeque)`** — інкапсульована всередині документа для організації черги погодження. Реалізує принцип **FIFO** (First In, First Out), оскільки етапи підписання мають відбуватися у суворо визначеному бізнес-порядку.

---

## 🚀 Функціонал сервісу
Клас-сервіс `DocumentRegistry` реалізує такі базові операції:
* **Додавання:** реєстрація нового документа з перевіркою унікальності ID.
* **Пошук:** миттєве знаходження документа за ключем.
* **Перегляд:** послідовний обхід реєстру документів за допомогою `entrySet()`.
* **Оновлення (Обробка черги):** проведення поточного етапу погодження та просування документа по черзі (`peek()`, `poll()`).
* **Видалення:** вилучення документа з реєстру.
